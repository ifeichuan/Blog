# Umami 修复说明

## 目标

1. 显示当前页面正在浏览的人数。
2. 显示每个文章 URL 路径的访问数据。

## 官方接口依据

来源：
- https://docs.umami.is/docs/api

关键接口：
- `GET /api/websites/:websiteId/active`
  - 返回当前活跃访客数
  - 响应示例：`{ "visitors": 5 }`
  - 适合“当前有多少人正在看”
- `GET /api/realtime/:websiteId`
  - 返回最近 30 分钟的实时数据
  - `totals.visitors` 是实时访客数
  - `series.visitors` 可用于绘制趋势
- `GET /api/websites/:websiteId/stats`
  - 支持 `path` 等过滤条件
  - 返回汇总统计
  - 适合按文章路径拿累计访问量/访客数
- `GET /api/websites/:websiteId/pageviews`
  - 支持 `path` 过滤
  - 返回 pageviews / sessions 的时间序列
  - 适合做按路径的时间分布图，不适合作为单个总数的唯一来源

Cloud 端点：
- 实际 Cloud API client 端点是 `https://api.umami.is/v1`
- 现有 `@umami/api-client` 也是按这个端点拼接请求

## 现在的问题

1. `src/actions/umami.ts` 里的真实请求逻辑被整段注释掉了，当前直接返回 `0`。
2. `wrangler.jsonc` 里的 `UMAMI_API_CLIENT_ENDPOINT` 一度写成了错误的根域名，导致请求打到了 404。
3. `src/components/BlogList.astro` 现在用的是 `/blogs/${p.id}`，但旧代码和 `src/pages/rss.xml.js` 里还混着 `/blog/...`。
4. 本地 `.env` 只有 `UMAMI_API_KEY`，没有 `UMAMI_WEBSITE_ID` 和 endpoint，开发环境即使恢复调用也可能拿不到完整配置。

## 修复方案

### 1. 恢复 Umami 服务端请求

把 `src/actions/umami.ts` 恢复成真实实现，不再返回固定 0。

建议拆成两个方法：
- `getActiveVisitors()`
- `getArticleStats(path)`

实现方式优先用服务端 `fetch` 直连 Umami HTTP API。

原因：
- 同样的查询参数下，裸 `fetch` 能返回真实统计
- 当前 `@umami/api-client` 在这套调用里返回了错误的 `0`
- 直接请求更容易排查，也更贴近官方接口定义

### 2. 实时人数用 active 接口

“当前有多少人正在看”优先用：
- `GET /api/websites/:websiteId/active`

原因：
- 直接返回当前活跃访客数
- 语义和需求最接近

### 3. 文章统计用 path 过滤

文章页统计优先用：
- `GET /api/websites/:websiteId/stats`

返回里取：
- `visitors`：独立访客数
- `pageviews`：浏览量

如果页面文案想表达“多少人看过”，用 `visitors` 更贴近。
如果想表达“热度/访问次数”，用 `pageviews` 更贴近。

### 4. 对齐 URL 路径

所有文章路径统一成当前真实路由：
- `/blogs/${post.id}`

同时把 RSS 里的链接也改成同一套路径，避免统计和页面地址不一致。

### 5. 对齐本地环境变量

本地开发要补齐：
- `UMAMI_API_KEY`
- `UMAMI_WEBSITE_ID`
- `UMAMI_API_CLIENT_ENDPOINT=https://api.umami.is/v1`

代码层也要兼容错误 endpoint：
- 如果环境变量里是 `https://api.umami.is`
- 运行时自动归一化成 `https://api.umami.is/v1`

## 风险点

1. 如果 Umami 里记录的路径和站点当前真实路径不一致，统计会一直是 0。
2. 如果本地只配了 API key，没配 website id，恢复代码后仍然查不到数据。
3. 如果文案继续写“热度”，但实际取的是 `visitors`，语义要统一。

## 推荐落地顺序

1. 先恢复 `src/actions/umami.ts` 的真实请求。
2. 再把路径统一到 `/blogs/...`。
3. 最后修正 `wrangler.jsonc` 和本地 `.env`。
